# 개발 절차

## 1. 프로젝트 목표와 범위

Stock Backend는 본인 토스증권 계좌를 사용하는 개인 전용 AIM 서버입니다. 국내·미국 주식 및 ETF를 다룹니다. 예약 실행을 기본으로 하되 수동 실행도 지원할 계획입니다. AI 월간 한도에 도달하면 AI 분석 및 신규 투자 실행을 멈춥니다.

현재 코드는 시작 골격입니다. 토스 API, AI, 데이터베이스 테이블, 예약 매매, PAPER 주문 시뮬레이터는 아직 구현되어 있지 않습니다. 서버 상태 및 대시보드 연결 상태 API만 존재합니다. 실제 투자 데이터나 주문 결과를 임의 값으로 대체하지 않습니다.

## 2. 기술과 로컬 환경

- Java 17, Spring Boot 4, Maven
- MariaDB, JDBC, MyBatis XML Mapper
- 기본 백엔드 포트: 38081
- 프론트 개발 서버: 38080, /api 경로를 백엔드로 프록시
- 기본 실행 모드: PAPER
- 실주문 기본값: 비활성

MariaDB에 stock 데이터베이스와 개발 계정을 준비합니다. 현재 application.yml의 접속 기본값은 localhost:3306, 데이터베이스 stock, 사용자 stock, 빈 비밀번호입니다. 개발 PC의 실제 환경에 맞게 수정하거나 배포 전 환경별 설정을 외부 비밀 저장소로 옮깁니다. 비밀번호·토스 API 키·AI 키는 저장소에 커밋하지 않습니다.

로컬 실행은 stock_be 디렉터리에서 Maven Spring Boot 실행 명령을 사용합니다. 애플리케이션 상태는 GET /api/system/health로 확인합니다. API 응답은 공통 ApiResponse 형식입니다.

## 3. 권장 구현 순서

1. 환경 설정과 DB 연결을 확정하고 초기 스키마·마이그레이션 방식을 정합니다.
2. 도메인 모델과 Mapper, 서비스, DTO, 컨트롤러 순서로 읽기·쓰기 기능을 구현합니다.
3. 종목 관심/허용/제외 목록과 전략 버전 및 위험 한도를 구현합니다.
4. 토스 시세·계좌 조회를 market/toss 어댑터로 구현하고 토스 응답을 내부 모델로 변환합니다.
5. PAPER 실행 엔진, 예약 및 수동 트리거, 중복 실행 방지, 실행 이력을 구현합니다.
6. AI 분석과 비용/호출 한도를 연결합니다. 한도 확인은 분석과 신규 주문 흐름보다 먼저 수행합니다.
7. PAPER 운영으로 데이터 신선도, 시장 시간, 실패 복구, 주문 중복 방지를 확인합니다.
8. 별도 검토 후에만 실계좌 주문 기능을 구현하고 기본 비활성 상태를 유지합니다.

각 단계는 작은 기능 단위로 완료하고 API 계약, DB 스키마, 화면 연동 지점을 함께 갱신합니다.

## 4. 코드 배치 규칙

도메인별 기능은 controller, service, dto, mapper, domain 패키지로 나눕니다. 컨트롤러는 HTTP 요청과 응답 변환을 담당하며 투자 판단, DB 로직, 외부 API 세부사항을 직접 포함하지 않습니다.

- controller: 요청 경로, 검증된 입력 전달, 응답 형식 지정
- service: 업무 규칙, 트랜잭션 경계, 유스케이스 오케스트레이션
- dto: API 입력·출력 전용 객체
- mapper: MyBatis 인터페이스 및 SQL 호출
- domain: 저장·업무 모델
- resources/mapper: SQL Mapper XML
- config: 인프라와 프레임워크 설정
- common: 공통 응답, 예외, 유틸리티

외부 시스템은 어댑터로 격리합니다. 토스 API 응답 타입을 업무 도메인 전반에 직접 노출하지 않습니다.

## 5. 투자 실행 변경 절차

매매 실행 경로를 바꾸는 작업은 다음 순서를 지킵니다.

1. 실행 모드가 PAPER인지 확인합니다.
2. AI 사용 한도와 전체 중지 상태를 우선 검사합니다.
3. 시장 개장 여부와 시세 시간 정보를 검사합니다.
4. 전략 버전, 허용 종목, 투자 한도, 보유 수 제한, 현금 비중을 검증합니다.
5. 동일 실행·동일 신호의 중복 처리를 막습니다.
6. 판단 근거, 시세 시각, 전략 버전, 실행 결과 또는 중단 사유를 저장합니다.
7. 실계좌 주문은 PAPER 경로와 분리하고 별도 활성화 없이는 호출되지 않게 합니다.

AI 한도 초과 시 우회 호출이나 임의의 기본 분석으로 진행하지 않습니다. 한도 도달 사유를 기록하고 신규 매매 판단을 멈춥니다.

## 6. 변경 시 문서와 전달 사항

모든 백엔드 변경은 관련 문서를 같은 변경으로 반영합니다.

- API 변경: 01-architecture.md의 API 계약 및 프론트 연동 설명
- 테이블/필드/인덱스 변경: 설계 문서의 데이터 모델과 DB 변경 이력
- 외부 API·권한·요청 제한 변경: 어댑터 설계와 설정 안내
- 실행/위험/AI 한도 변경: 실행 흐름과 안전 정책
- 실행 방법·의존성·프로파일 변경: 이 문서
- 모든 변경: 02-change-log.md에 날짜, 변경 요약, 영향, 검증 상태를 기록

완료 보고에는 변경 파일, 기능 범위, 수행한 검증과 미검증 항목을 구분해 적습니다. 사용자가 검증을 요청하지 않은 경우 자동으로 테스트를 실행하지 않습니다.
