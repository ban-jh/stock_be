# 개발 순서와 진행 현황

## 목표
본인 토스증권 계좌만 연결하는 개인 AIM 서버. 국내·미국 주식과 ETF, 예약/수동 실행을 지원하고 AI 월간 한도 도달 시 신규 분석과 매매 실행을 멈춥니다. 실계좌 주문은 PAPER 검증 뒤 별도 단계입니다.

## 순차 개발 항목
1. 기반 설정과 핵심 DB 스키마 — MariaDB 접속정보 환경변수화, 핵심 테이블 초안. **초안 완료**.
2. 도메인/DB 접근 — 전략 버전·종목 등록/조회/상태 변경, 실행 이력 조회, AI 사용량 누적/조회. **구현 초안 완료**.
3. 토스증권 연결 — 인증·토큰, 시세/계좌 어댑터, 호출 제한과 오류 처리. **읽기 전용 범위 완료:** DPAPI 개인 토큰 보관, Bearer 인증, 조회 API, 기본 호출 간격, 429 전달, 현재가/계좌 DTO와 계좌번호 마스킹 구현. 인증 없는 요청의 401 차단과 실제 현재가 2건·계좌 1건·보유 조회 성공을 확인. 보유 항목 DTO는 보유 종목 확인 시 보강하며, 자동 실행 중지 연계는 6단계, 프론트 호출은 7단계에서 진행. 상세는 설계/03-toss-api.md 참조.
4. 위험 제한/중지 — AI 한도, PAPER 고정, 전체 중지, 장 시간·시세 신선도 확인.
5. PAPER 주문 엔진 — 신호, 가상 주문·체결, 잔고, 근거 보존.
6. 예약·수동 실행 — 같은 유스케이스, 멱등성, 잠금, 이력과 재시도.
7. 프론트 연동 API — 대시보드 및 전략/종목/실행 현황을 실제 데이터로 제공.
8. AI 분석과 전략 개선 제안 — 비용 한도, 설명 근거, 승인 전 미적용.
9. PAPER 운영 검증과 안정화 — 시장 시간대, 장애 복구, 데이터 지연, 중복 방지.
10. 실계좌 주문 — 앞 단계 검증 후 별도 구현, 기본 비활성 유지.

## 현재 단계
1단계에서 DB 접속정보를 환경변수로 분리하고 dbscript/01_schema_core.sql에 핵심 테이블 초안을 추가했습니다. 상세 명세와 ERD는 docs/설계/01-database-schema.md에 있습니다. 2단계 구현 초안은 완료했습니다. 3단계 읽기 전용 연결, Bearer 인증, 시세·계좌 DTO, 호출 제한 처리를 완료하고 DPAPI 토큰으로 로컬 API를 확인했습니다. 다음 순서는 4단계 위험 제한·전체 중지입니다. 자동 실행의 429 중지 연계는 실행 경로를 만드는 6단계에서 적용합니다.

## 진행할 때 문서도 갱신
각 코드 변경과 같은 작업에서 docs/01-architecture.md와 docs/02-change-log.md를 수정합니다. 실행 절차/설정이 바뀌면 docs/00-development-workflow.md도 갱신하고 이 로드맵의 상태를 업데이트합니다. 기능이 미구현인지 완료인지 문서에서 구분합니다.
