# 3단계 토스증권 API 연결 사전 준비

## 목적과 범위

3단계는 토스증권 Open API를 백엔드에서 호출할 수 있도록 인증·토큰, 국내/미국 시세 및 계좌 조회 어댑터, 호출 제한 대응을 구현하는 단계입니다. 이 문서는 사용자가 준비하고 확인할 사항과 실행 방법을 정리합니다. **DPAPI 개인 토큰을 이용한 Bearer 인증과 읽기 전용 시세·계좌·보유 조회를 확인했습니다. 프론트엔드 호출은 7단계에서 연결합니다. 구현 내용은 설계/03-toss-api.md를 참고하세요.**

현재 목표 범위는 본인 명의 토스증권 계좌 하나를 연결하고 국내·미국 주식 및 ETF를 조회하는 것입니다. 첫 연동은 읽기 전용 시세/계좌 확인으로 제한하며 주문 API는 후속 단계에서 별도로 다룹니다.

## 준비 항목 요약

| 순서 | 사용자가 할 일 | 준비 완료 기준 |
|---|---|---|
| 1 | 토스증권 계좌 및 Open API 이용 신청 | 본인 인증·계좌 인증 완료, 앱키와 시크릿키 발급 |
| 2 | 호출 서버의 공인 IP 확인 및 허용 IP 등록 | API를 실행할 서버 IP가 Open API 설정에 등록됨 |
| 3 | API 이용 범위·약관·데이터 사용 조건 확인 | 개인 매매 목적 이용, 제3자 제공/배포/상업적 이용 금지 이해 |
| 4 | 국내·미국 주식 및 ETF 조회 대상 확인 | 필요한 시장/종목이 API에서 제공되는지 확인 |
| 5 | 호출 한도와 비용 정책 확인 | 최신 Rate Limits 및 수수료/시세 정책 확인, 자동 실행 주기 결정 |
| 6 | 인증 정보의 로컬 보관 준비 | 비밀값을 문서·소스·채팅에 남기지 않고 서버 환경으로 주입할 준비 |
| 구현 후 | 읽기 전용 연결 점검 | 토큰 발급 후 국내/미국 종목 현재가를 각 1회 확인 |

## 사용자 준비 절차

### 1. 토스증권 Open API 이용 신청 및 키 발급

**간략 내용 (명령어)**

`토스증권 Open API 페이지 → 이용 신청 → 약관 동의 → 본인 인증 → 계좌 인증 → 앱키/시크릿키 발급`

> 앱키와 시크릿키 값은 문서에 기록하지 않습니다. 백엔드 실행 시 OS 환경변수로 전달하세요. 이미 Git에 커밋되었거나 저장소를 공유했다면 토스 설정에서 해당 키를 폐기하고 재발급하세요.

**상세 설명**

<details>
<summary>발급 절차와 확인 사항</summary>

1. 토스증권 계좌를 보유한 본인 계정으로 [토스증권 Open API](https://p.tossinvest.com/ko/open-api) 페이지에 접속합니다.
2. Open API 신청 화면에서 약관을 확인하고 본인 인증과 계좌 인증을 마칩니다. 공식 약관상 계좌 보유 고객이 신청하고, 회사가 발급한 앱키/시크릿키로 API를 인증합니다.
3. 발급 후 다음 값을 안전한 개인 비밀 저장소에 기록합니다.
   - 앱키/클라이언트 ID (`client_id` 계열)
   - 시크릿키/클라이언트 시크릿 (`client_secret` 계열)
   - 연결할 계좌 식별 정보(필요한 경우 API 문서가 요구하는 계좌 순번 등)
4. 신청 화면에서 테스트/운영 구분이나 API별 권한을 선택하게 되면 **시세와 계좌 조회에 필요한 최소 권한만** 활성화합니다. 실제 주문 권한은 지금 단계에서 켜지 않습니다.
5. 키가 재발급되거나 폐기되면 기존 실행 환경의 키도 갱신해야 합니다. 키 자체는 이 문서, 소스코드, 이슈, 채팅에 붙여 넣지 않습니다.

발급 UI와 권한 항목은 토스증권 운영 화면에서 변경될 수 있으므로 신청 당일 화면의 안내를 기준으로 합니다. 이용 신청이 완료되지 않거나 발급 항목이 보이지 않으면 임의로 다른 키를 만들지 말고 Open API 안내/고객센터에서 계정 상태와 신청 조건을 확인합니다.

</details>

### 2. API를 호출할 서버의 IP 허용

**간략 내용 (명령어)**

`WTS 설정 → Open API → 허용 IP 관리 → 백엔드 실행 서버의 고정 공인 IP 등록`

**상세 설명**

<details>
<summary>개발 PC와 운영 서버의 IP 등록 방법</summary>

토스 API는 등록되지 않은 IP의 요청을 거부할 수 있습니다. 허용 IP는 브라우저에서 Open API 신청을 한 PC가 아니라 **실제로 Spring Boot 백엔드가 외부 API를 호출하는 장비/네트워크의 공인 IP**입니다.

1. WTS의 `설정 > Open API > 허용 IP 관리`로 이동해 API 호출을 허용할 IP를 등록합니다. 메뉴 명칭은 변경될 수 있으므로 토스의 최신 연동 가이드 화면을 확인합니다.
2. 로컬 개발 중에는 개발 PC의 공인 IP를 등록합니다. 개발 PC의 공인 IP가 바뀌면 다시 등록해야 합니다.
3. 자동 실행을 상시 운영할 서버를 별도로 둘 경우 그 서버의 고정 공인 IP도 등록합니다. 공유기 뒤의 사설 IP(`192.168.x.x`, `10.x.x.x`)가 아니라 외부에서 보이는 공인 IP를 등록합니다.
4. VPN, 프록시, 클라우드 NAT를 사용한다면 API 요청의 실제 출구 IP를 확인합니다. 해당 네트워크 사업자의 콘솔/관리자 설정에서 확인한 값과 토스 등록값을 일치시킵니다.
5. IP를 바꾸거나 서버를 옮기기 전에 새 IP를 등록하고 읽기 전용 조회로 확인합니다.

개발 PC와 서버의 IP 주소를 이 문서나 Git에 기록할 필요는 없습니다. 허용 IP 등록 여부만 체크리스트로 관리합니다.

</details>

### 3. 약관과 시세 데이터 사용 조건 확인

**간략 내용 (명령어)**

`Open API 이용 약관 확인 → 개인 본인의 매매 목적만 사용 → 제3자 제공/배포/상업적 이용 금지 조건 확인`

**상세 설명**

<details>
<summary>본인만 사용하는 AIM에서 지켜야 할 경계</summary>

현재 공식 [Open API 이용 약관](https://home.tossinvest.com/ko/terms/v2?id=752)은 국내·해외 주식 시세 정보를 **개인투자자 본인의 매매 목적**으로 이용하도록 제한하고, 제3자에게 제공·배포하거나 상업적으로 활용하는 것을 금지합니다. 법인 고객은 Open API 이용 대상에서 제외되며, 법인 시세 이용에는 별도의 데이터 제공 계약이 요구될 수 있습니다.

따라서 이 AIM은 본인만 접근하도록 인증을 걸고, 시세/계좌 응답을 다른 사람이나 공개 서비스에 노출하지 않도록 설계합니다. 외부 사용자 계정, 공개 대시보드, 시세 데이터 재배포, 유료 서비스로 확장하려면 현재 개인용 API 사용 범위로 진행할 수 있다고 가정하지 말고 별도 이용 조건을 확인해야 합니다.

또한 키는 본인 이외의 사람에게 공개·양도·대여하지 않습니다. 시세와 주문 기능의 실제 허용 범위는 신청 시점의 약관과 Open API 안내를 우선합니다.

</details>

### 4. 국내·미국 주식 및 ETF 지원 범위 점검

**간략 내용 (명령어)**

`API 가이드 → Market Data 종목 조회 → 국내 종목 1개 + 미국 종목 1개 + 각 시장 ETF 1개씩 조회 가능 여부 확인`

**상세 설명**

<details>
<summary>종목 코드와 시장 지원을 확인하는 방법</summary>

토스증권 안내는 하나의 Open API 연동으로 국내 및 해외 주식의 시세 조회와 주문을 지원한다고 설명합니다. Market Data 문서에는 현재가, 호가, 체결, 상·하한가, 캔들 API가 기재되어 있으며 현재가 다건 조회는 최대 200개 심볼을 받습니다. 미국 종목 코드는 예시로 `AAPL`, 국내 종목은 `005930`과 같은 심볼을 사용합니다.

구현 전에 [Market Data 가이드](https://developers.tossinvest.com/docs/market-data)에서 다음을 직접 확인합니다.

- 국내 주식과 미국 주식 각각 현재가 조회가 가능한지
- 국내 상장 ETF와 미국 상장 ETF의 심볼/거래소 코드 표현 방식
- 원하는 ETF가 계좌에서 거래 가능한 상품인지와 시세 API에서 조회 가능한지
- 미국 시장 데이터의 통화, 거래 시간, 시간대, 장 전/장 후 값의 의미
- 캔들 조회 기간·주기·최대 조회 수 및 데이터 누락 규칙

ETF는 API 심볼 조회 가능 여부와 실제 계좌의 매매 가능 여부가 별개일 수 있으므로 두 가지를 각각 확인합니다. 초기 검증은 API가 돌려주는 시세를 읽기만 하고 주문은 보내지 않습니다.

</details>

### 5. 호출 제한·요금·자동 실행 주기 확인

**간략 내용 (명령어)**

`Market Data 가이드의 Rate Limits 확인 → 호출 헤더/429 처리 확인 → 필요한 조회 주기를 정하고 현재 요금 안내 확인`

**상세 설명**

<details>
<summary>호출량 계획과 요금 확인</summary>

공식 문서는 호가·현재가·체결·상하한가를 `MARKET_DATA`, 캔들 차트를 `MARKET_DATA_CHART` 그룹으로 나누며, 응답의 한도 관련 헤더를 확인하라고 안내합니다. 한도 초과는 HTTP `429`로 나타날 수 있고, 약관은 회사가 호출 제한을 게시하며 트래픽 상황에 따라 별도 공지 없이 제한을 조정할 수 있도록 합니다.

시작 전 확인할 항목:

1. 최신 가이드에서 그룹별 요청 한도, 시간 구간, 응답 헤더, 토큰 발급 제한을 확인합니다. 문서나 코드에 오래된 숫자를 고정값으로 복사하지 않습니다.
2. 예약 분석이 실행될 때 감시 종목을 묶어 조회할 수 있는지 확인합니다. 필요하지 않은 초단위 폴링은 피하고, 장 중 실시간 호가/체결이 실제로 필요한 경우 웹소켓 사용 조건과 구독 한도도 봅니다.
3. 429나 네트워크 오류가 발생하면 지수형 대기 등으로 재시도하고, 한도를 계속 초과할 경우 자동 실행을 멈추도록 요구사항에 반영합니다.
4. Open API 사용료, 실시간/지연 시세 구분, 주문 수수료와 세금은 연결 기능 및 거래 시장에 따라 다를 수 있으므로 신청 화면과 토스증권의 최신 요금·수수료 안내를 확인합니다. 확인 결과를 임의로 무료라고 가정하지 않습니다.

요금/한도 확인 결과와 실제 자동 실행 주기를 정한 뒤 백엔드 설정값으로 옮깁니다. 개인용 토스 계정에 적용되는 숫자나 금액이 화면에 표시되면 값과 확인 일자를 기록하되, 계정 정보는 기록하지 않습니다.

</details>

### 6. 인증 정보 보관과 서버 설정 준비

**간략 내용 (명령어)**

```powershell
# stock_be 프로젝트 루트에서 실행합니다. 기존 client 키를 DPAPI로 보호합니다.
.\protect-local-secrets.ps1
# DPAPI 복호화와 Spring Boot 실행을 한 번에 수행합니다.
.\run-local.ps1
```

**상세 설명**

<details>
<summary>키를 소스와 문서에 남기지 않는 방법</summary>

프로젝트 루트의 `.env.properties`가 로컬 설정 파일입니다. `application-local.yml`이 이 파일을 선택적으로 가져옵니다. `.gitignore`의 `.env.*` 규칙에 따라 `.env.properties`는 Git에서 제외되고 `.env.example`만 예제로 추적됩니다. `protect-local-secrets.ps1`은 현재 파일의 앱키·시크릿키 값을 Windows 사용자 계정 DPAPI 암호문으로 바꾸며, 값 자체를 출력하지 않습니다. 암호화 후에는 반드시 `run-local.ps1`로 실행해야 합니다. 이 암호문은 같은 Windows 사용자 계정에서만 복호화됩니다.

토스 조회 컨트롤러를 호출하려면 개인 인증용 `STOCK_API_ACCESS_TOKEN`도 설정합니다. 아래 명령은 32바이트 난수를 생성합니다. 출력값을 로컬 `.env.properties`에 `STOCK_API_ACCESS_TOKEN=`으로 입력한 뒤 `protect-local-secrets.ps1`을 실행하면 토큰도 DPAPI로 암호화됩니다. 토큰 값을 문서·저장소·채팅에 붙여넣지 않습니다.

```powershell
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
[Convert]::ToBase64String($bytes)
```

Vue 개발 서버는 API 요청에 `Authorization: Bearer <토큰>` 헤더를 보내야 합니다. 미설정 토큰은 503, 잘못된 토큰은 401을 반환합니다. CORS는 `localhost:38080` 및 `127.0.0.1:38080`만 허용합니다.

읽기 전용 연결 점검을 할 때에는 `.env.properties`에서 `TOSS_API_ENABLED=true`, `TOSS_SMOKE_CHECK=true`로 설정합니다. 서버는 `run-local.ps1`로 실행하고, 현재가 2건과 계좌 1건 이상이면 성공 메시지가 나옵니다. 시세 값과 계좌번호는 출력하지 않습니다. 확인이 끝나면 `Ctrl+C`로 종료합니다. 앱키·시크릿키를 문서나 `.env.example`에 기록하지 않습니다.

- 실제 키를 `application.yml`, Java/Vue 소스, SQL, 문서, Git 커밋, 채팅에 입력하지 않습니다.
- 로컬 검증은 `.env.properties`의 DPAPI 암호문을 `run-local.ps1`로 복호화해 현재 실행 프로세스에만 전달합니다. PowerShell/Maven 실행이 끝나면 임시 환경변수를 복구합니다.
- DPAPI 암호문은 같은 Windows 계정에서만 복호화됩니다. Windows 계정을 바꾸거나 PC를 이동하면 원래 키를 다시 등록하고 암호화해야 합니다.
- 앱키/시크릿키는 프론트엔드 브라우저로 보내지 않습니다. 백엔드만 보관·사용합니다.
- 화면 공유, 로그, 예외 메시지에 토큰이나 키 전체를 출력하지 않습니다. 키가 노출되면 토스 설정에서 폐기/재발급합니다.

</details>

### 구현 후. 읽기 전용 API 연결 점검

**간략 내용 (명령어)**

`토큰 발급 → 현재가 조회 API를 국내 1종목·미국 1종목 각각 1회 호출 → 응답/권한/시각 확인`

**상세 설명**

<details>
<summary>연동 구현 후 사용자가 확인할 점검 절차</summary>

위 6단계에서 `.env.properties`의 토스 설정을 켜고 `run-local.ps1`을 실행합니다. 토큰 URL이나 요청 필드는 [인증 가이드](https://developers.tossinvest.com/docs/auth)를 따르며, 이 점검은 읽기 전용 현재가·계좌 목록만 호출합니다. `/api/toss/**`를 프론트엔드에서 호출할 때에는 개인 Bearer 토큰을 설정해야 합니다.

1. 백엔드 프로세스에 앱키/시크릿키를 주입하고, 토스의 토큰 발급 API에서 인증 토큰을 얻습니다.
2. 인증 헤더를 적용해 현재가 API를 국내 대형주 1개와 미국 대형주 1개에 각각 호출합니다.
3. 국내 ETF 및 미국 ETF를 추가 확인하고, 심볼·통화·거래소·타임스탬프가 기대와 맞는지 봅니다.
4. 허용 IP 오류, 인증 오류, 미지원 심볼, 시장 휴장, 429 응답을 구분해 기록하되 비밀값은 로그에서 마스킹합니다.
5. 요청 한도 헤더와 재시도 결과를 확인하고, 자동 실행은 낮은 빈도로 시작합니다.

이 단계가 완료되면 호출 성공/실패와 미지원 상품을 기록합니다. 주문/매매 검증은 별도 PAPER 단계 이후에만 다룹니다.

</details>

## 3단계 착수 기준

아래는 3단계 구현에 앞서 확인하는 준비 항목입니다. 사용자는 사전 준비가 완료되었다고 알려주었으며, 실제 요청 성공 여부는 환경변수를 적용한 읽기 전용 점검으로 확인해야 합니다.

- [ ] Open API 신청 및 본인 인증 완료, 앱키/시크릿키 발급 완료
- [ ] 로컬 개발 또는 실행 서버의 출구 공인 IP 등록 완료
- [ ] 개인 매매 목적 시세 사용 및 비공개 조건 확인 완료
- [ ] 국내·미국 주식 및 양 시장 ETF의 심볼/조회 가능 여부 확인 완료
- [ ] 최신 호출 제한 및 요금/시세 조건 확인, 예약 호출 주기 결정
- [ ] 비밀값을 로컬 환경으로 전달할 방법 준비

사용자는 실제 앱키·시크릿키와 개인 접근 토큰을 공유하지 않아도 됩니다. 구현에는 환경 변수 이름과 비밀값 입력 경로만 사용합니다.
